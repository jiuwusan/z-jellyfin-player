# 订阅协议 v2

## 可选代理（Android 0.6.58 起）

`connection.proxy` 缺失或为 `null` 表示直连 Jellyfin，Hub 发布直连时省略此字段；如果对象存在，原有 type/host/port/username/password 校验保持，空对象、缺少字段或错误值均拒绝，不能默默直连。订阅草稿 `proxyId` 为空字符串时不引用代理实体，其余授权和策略引用仍必填。保存草稿不改变已发布快照。

直连快照的 `minClientVersionCode` 至少为 72，由 Hub 自动提升；既有代理快照继续兼容原支持版本。Android 直连显式使用 `Proxy.NO_PROXY`，不继承系统 HTTP 代理，不发送代理认证头；系统 VPN 路由仍由操作系统决定。配置切换需要候选连接验证，播放中仍延迟应用；连接失败不切换模式。手机必须能直接到达下发的服务器地址，包括其路径前缀。设置页直连时显示「连接方式：直连」。参考 [直连样例](subscription-v2.direct.example.json) 和 [实施需求](../requirements/直连模式.md)。

实现日期：2026-11-24。服务端以 `internal/domain/config.go`、`internal/httpapi/server.go` 为准；Android 对应 ManagedConfiguration、SubscriptionClient、SubscriptionController。结构见 [JSON Schema](subscription-v2.schema.json)，示例见 [配置样例](subscription-v2.example.json)。样例均为虚构数据。

## 链接和身份

完整链接例如 `https://hub.example.com/api/v1/subscription/config#{token}`。创建/轮换 API 仅返回 `api/v1/subscription/config#{token}` 相对路径，浏览器按当前页面地址拼接完整链接，保留部署路径前缀。后台访问不限制域名、IP、端口或 HTTP/HTTPS，也不配置 HUB_PUBLIC_URL；复制订阅时应使用手机可达的 HTTPS 后台地址。

管理后台使用 hash 路由（如 `/任意前缀/#/subscriptions`），页面 hash 不属于部署前缀，也不能拼入订阅 API 地址。订阅链接的 `#TOKEN` 仅存令牌，与后台的 `#/页面路径` 独立；静态资源、API 和订阅链接均从 `#` 前的物理目录推导，无固定 `/hub/` 前缀。

链接不包含订阅 ID，token 唯一定位订阅；数据库内部仍保留随机 ID 关联模板、历史与反馈。token 为 32 随机字节的无填充 Base64URL 编码（43 字符）。每人一个订阅，可供其多台设备使用。支持随机生成、手动指定与恢复原令牌。服务器保留 SHA-256 摘要用于鉴权，并使用现有主密钥 AES-GCM 加密保存令牌副本，AAD 绑定订阅 ID；管理员可通过独立接口按需复制，普通列表不返回令牌或密文。令牌必须为规范的 43 字符编码（拒绝 CR/LF、空白和非规范尾位），全库唯一；重复绑定返回 409，非法输入返回 400，原绑定保持不变。已有订阅通过 POST /api/v1/admin/subscriptions/{id}/token 设置，空字符串表示随机轮换；新建订阅可在 JSON 的 token 字段指定，留空随机生成。链接本身是访问凭据，不得记录、截图或分享给其他人。

客户端剥离 fragment，将 token 放入 `Authorization: Bearer ...`。不接受 URL 用户信息、query、非 HTTPS 地址或跨站重定向；不跳过系统证书校验。订阅使用独立直连网络客户端，不依赖或附带下发的 HTTP 代理/Jellyfin 凭据。端点不支持在浏览器地址栏直接获取配置，因为 fragment 不会作为 HTTP 请求发送。

## 获取完整快照

### 管理员复制与旧订阅补录

| 管理接口（前缀 `/api/v1/admin`） | 行为 |
| --- | --- |
| `POST /subscriptions/{id}/link` | 有效管理员会话及 CSRF 下按需返回 `{link}` 相对链接；未保存密文的旧订阅返回 409 / TOKEN_NOT_SAVED |
| `POST /subscriptions/{id}/link/restore` | JSON `{token}` 必须匹配当前订阅摘要，匹配后加密保存并返回原相对链接；不匹配返回 400 / TOKEN_MISMATCH，不改变摘要、版本或发布状态 |

以上接口均为 `Cache-Control: no-store`。普通订阅列表只增加 `hasSavedToken` 能力标记，不返回令牌/密文。创建及设置/轮换令牌原子更新摘要和密文；旧数据库自动增加可空密文列，旧摘要照常鉴权。前端补录接受完整原链接或 43 位令牌，路径必须为固定订阅端点，不接受 query 或 URL 用户信息；仅提取并提交令牌，不请求输入地址。补录链接来源不限制域名，复制后的地址仍按当前后台地址及子目录生成。若原入口不同，应从设备可达的原 HTTPS 入口打开后台后复制。

此变更不改变手机订阅请求、JSON Schema 或配置版本，Android/iOS 无需为此修改。旧数据无法从摘要逆推令牌，必须由管理员提供备份或手机保存的原链接。

`GET /api/v1/subscription/config`

必需请求头：Authorization、`X-Client-Version-Code`（正整数，v2 Android 为 57）。已有成功快照时附带 `If-None-Match`。响应体上限 64 KiB。

| 状态 | 行为 |
| --- | --- |
| 200 | JSON 完整配置及 ETag；客户端严格校验后构造候选 |
| 304 | 版本未变；仅更新检查时间，不重新登录或重建播放器 |
| 401/403 | 链接不可用；当前正在使用的订阅标为失效，阻止新播放 |
| 410 | 订阅已停用；与上述失效处理一致 |
| 409 | 尚未发布；保留已有可用配置，提示稍后重试 |
| 426 | App 版本不满足 minClientVersionCode；保留旧配置并提示升级 |
| 429/5xx/超时 | 保留最后成功配置，退避重试 |

服务端在比较 ETag 前检查令牌、启用状态和客户端版本，不能使用 304 绕过停用。响应 `Cache-Control: private, no-cache`，`Vary: Authorization, X-Client-Version-Code`。代理不得共享缓存配置响应。错误体为 `{ "code": "脱敏类别", "message": "固定提示" }`，不包含地址、密码或令牌。

核心字段：schemaVersion 固定 2；serverInstanceId 为数据库持久化的 32 位小写十六进制实例标识；subscriptionId 为内部订阅标识，不参与链接解析；revision 在对应实例/订阅序列中从 1 递增；minClientVersionCode 为最低兼容版本；refreshIntervalSeconds 为 300～86400，默认 900。connection 包含 HTTP 代理和 Jellyfin 授权；playback 为分辨率及音视频合计码率上限（bps）。0 码率表示自动，auto/screen 分辨率语义沿用客户端现有策略。枚举见 Schema。

不下发字幕或音轨偏好。首选语言继续由 App 读写 Jellyfin 账号设置；播放时选轨、关闭字幕继续由播放会话处理。

## 应用与恢复

首次导入、代理或授权改变时，先通过候选代理调用 Jellyfin 登录；成功后才覆盖原配置。解析、连接或鉴权失败不得清空最后成功配置。缓存使用 Android Keystore 独立密钥加密；已有受信任的 v1 缓存会在设备内自动转换旧 ID 链接为固定地址、迁移为待验证来源并清除旧 ETag，首次联机获取 v2；网络响应不接受 v1；不保留旧手动配置入口，也不读取旧配置自动登录。未配置订阅或缓存损坏时展示导入入口。

播放期间不替换连接；已验证候选保留至退出播放，随后应用。后续暂时刷新失败不丢弃这个候选。画质更新不重建当前流，在下一次取流或切集时采用；同一影片切音轨/字幕仍保留本次播放的策略。显式停用不强行中断当前流，但禁止新取流/切集。

同一 serverInstanceId + subscriptionId 的版本必须单调增加，相同版本内容不得改变，即使换令牌或访问入口也不能绕过。数据库重建会生成新 serverInstanceId；新建订阅可使用原令牌，客户端检测新来源后必须重新验证代理和 Jellyfin，成功后才接受新来源的版本 1。恢复失败保留最后可用配置，恢复停用状态也无需重新输入链接。回滚发布一个更高版本的旧内容。令牌轮换独立于配置版本，旧链接立即失效。客户端启动先用成功缓存，再在前台异步检查；默认约 15 分钟刷新，带抖动和退避，不要求后台常驻。Hub 短暂不可用时仍可使用缓存，但媒体代理与 Jellyfin 自身必须可用。已下发的凭据不能远程抹除，停用需客户端下次成功联机获知，不能保证离线即时撤权。

## 状态反馈

`POST /api/v1/subscription/feedback`，同一 Bearer 身份，JSON 字段：deviceId（16～128 字符设备标识）、platform（android/ios）、versionCode、revision、status、errorCode。status 为 synced/applied/pending/error；errorCode 为 NETWORK/PROXY_AUTH/JELLYFIN_AUTH/UNSUPPORTED_CONFIG/REVOKED 或空字符串。不得上传原始异常、URL、认证信息。

服务端按订阅散列设备标识，每个订阅仅保存最近 50 条反馈。第一版 Android 主动上报 applied/pending；后台展示最近反馈，不代表设备当前在线。管理 API 与订阅身份隔离：登录 Cookie 为 HttpOnly/SameSite=Strict，浏览器 HTTPS 使用独立的 __Host-hub_session Secure Cookie，HTTP 使用 hub_session_http；管理写操作要求有效会话及 X-CSRF-Token，不再校验 Origin/Host 是否匹配或 Sec-Fetch-Site，不设固定地址白名单、不信任转发头推导公开地址。初始化仍需一次性码，登录仍需正确账号密码并限流；Origin 缺失、不同或无效不作为授权拒绝条件。Cookie 的 HTTPS 判断见部署文档，本次不改变 Android 订阅协议；草稿保存、预览、发布、回滚、启停和轮换各有独立操作。

## 加密边界

HTTPS 提供传输加密，JSON 响应内字段不再做自定义端到端加密，因此 TLS 终止入口能看到明文配置；Android 不接受 HTTP 订阅。服务器数据库实体和发布快照使用 AES-256-GCM，随机 nonce、带记录上下文 AAD，主密钥首次自动生成到独立 secrets 持久化卷（0600），不存入数据库或镜像。管理员密码 Argon2id 哈希；订阅 token 保留鉴权摘要与绑定订阅 ID 的加密副本，数据库/WAL/备份均不写入明文令牌。Android 成功快照与链接使用独立 Keystore AES-GCM 加密保存。

数据库与主密钥分别备份，错误密钥拒绝打开已有数据；丢失主密钥不能恢复凭据。不能将数据库静态加密理解为允许明文 HTTP 下发。
