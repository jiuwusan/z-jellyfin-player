# Jellyfin 家庭影音开发规范

适用于 `z-jellyfin-player` 中的 Android、iOS 和共享文档。新功能可按端独立落地，跨端共享行为约定和验收条件。

## 工程与边界

| 目录 | 工程基线 | 项目标识 |
| --- | --- | --- |
| `android/` | Android 原生，现有模块为 Java、Media3、OkHttp。JDK 21，`compileSdk 36`，Android 6.0 起。 | 安装包名和代码命名空间均为 `cn.jiuwusan.jellyfin.player`。 |
| `ios/` | SwiftUI，iOS 16 起。Xcode 工程与共享 Scheme 随仓库维护，模拟器可用于基础开发。 | `cn.jiuwusan.jellyfin.player`。 |
| `docs/` | 功能需求、交互原型与本规范。 | 共用一份需求和验收口径。 |

Android 新包可与旧验证版 `cn.jiuwusan.jellyfin.playbackprobe` 和旧家庭版 `cn.jiuwusan.jellyfin` 并存。首次安装新包时重新设置代理和授权。后续使用同包名、同签名覆盖安装时保留配置。

- UI 负责显示和用户操作，网络层负责产生 Jellyfin 请求并解析错误，播放层负责取流协商、解码与会话进度。小功能沿用项目的现有结构，避免为两端提前引入共用代码框架。
- UI 设计稿保留原有手机比例及评审布局，页面背景覆盖完整浏览器可视区；不要横向拉伸手机界面，不要因固定桌面仿真视口产生右侧或底部白色留白。截图使用对应画幅，保持设计原有比例。
- Android 维持现有 Media3 播放链路。iOS 在接入播放时先验证原生播放器对认证 HLS 和 HTTP 代理的行为，再确定网络到播放的接法。代理能力需覆盖 API、海报、播放清单和分片，按端实测。
- 需要改变登录、续播、播放画质或错误提示时，同时更新共享需求或验收条件，明确两个平台各自的实施状态。

## Jellyfin 行为约定

- HTTP 代理设置、服务器授权和播放画质按当前 App 保存。自动登录由当前账号和设备身份驱动，代理或登录失败的提示应区分，并允许重试。
- 密码和令牌使用 Android Keystore 或 iOS Keychain 保护。实际服务器地址、账号、令牌、连接配置和签名凭据只保存在设备或本地环境。日志仅记录必要的诊断字段，播放 URL 查询参数先脱敏。
- 继续观看以 Jellyfin 保存的位置为准。播放开始、进度和停止按同一会话上报，返回详情或首页后刷新观看状态。选季选集、已看完标识和设置确认以 [原型](../prototype/index.html) 的行为为参考。
- Android 默认将超出分辨率或码率上限的视频转为 H.264/AAC HLS，宽高限制为 `1920×1080` 并保持比例，音视频合计编码预算为 `4_000_000 bps`。画质可从设置页调整，覆盖安装时沿用已保存值或此默认值。编码预算、实际媒体码率与网络吞吐分别记录。
- 验证硬解需要记录实际输入编码、宽高、帧率、解码器与首帧。请求参数或界面上的画质标签只能作为辅助证据。

## 本地构建与验收

### Android

在 `android/` 执行：

```text
gradlew.bat :app:assembleDebug
```

macOS 或 Linux 可执行 `sh ./gradlew :app:assembleDebug`。APK 位于 `android/app/build/outputs/apk/debug/`。当前播放策略检查位于 `android/verification-src/cn/jiuwusan/jellyfin/player/PlaybackPolicyCheck.java`。有设备验收时优先使用 OPPO Reno5 K；红米 Note 17 Pro 用于必要的转码和硬解回归。

### iOS

在 Mac 上打开 `ios/JellyfinPlayer.xcodeproj`，使用 `JellyfinPlayer` Scheme。仓库根目录的模拟器构建命令：

```sh
xcodebuild -project ios/JellyfinPlayer.xcodeproj -scheme JellyfinPlayer \
  -configuration Debug -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

按本地 Xcode 配置选择真机签名团队。远程 Mac 上的构建任务使用独立临时目录和 DerivedData，保留共享设备上的其他工程与管理设置。

### 变更验收

- UI 变更核验正常、空数据和主要失败状态，检查返回位置和触控操作。
- 网络或播放变更核验登录、前后台重开、原流和转码、拖动进度及续播。涉及代理改动时，分别核对 API、海报和媒体请求的实际路径。
- 新增或改变协议行为时，用可复现的检查覆盖相应分支。两端验收各自记录构建结果、设备、App 版本和待验证项。

## 版本、提交与发布

- 在用户指定的分支开发。提交摘要用中文，格式为 `<类型>: <中文摘要>`，例如 `feat: 新增剧集详情与续播入口`。先核对变更范围和构建结果，再按用户指示提交或推送。
- Android 的 `versionCode` 和 iOS 的 `CURRENT_PROJECT_VERSION` 各自递增。包名、Bundle ID、签名变更前确认升级和数据迁移影响。
- Android 密钥库、iOS 私钥、签名描述文件、本地签名配置和安装包均放在仓库外。发布前核对安装包对应的环境和签名。
- 上传 TestFlight 后，在「测试内容」中标明测试环境或生产环境，简述本次变更与测试重点。

### 加载组件的受控真机检查

Android 可执行 `gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest`，在指定设备覆盖安装应用及 `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk` 后，运行 `adb -s <序列号> shell am instrument -w cn.jiuwusan.jellyfin.player.test/cn.jiuwusan.jellyfin.player.LoadingTransitionCheck`。结果须包含 `ALL_PASS`。此检查短时替换目标进程的显示区域以验证加载组件，不改服务或已保存配置；结束后卸载专用测试包 `cn.jiuwusan.jellyfin.player.test` 并重新打开主 App。不要卸载主包或清空其数据。

同一测试入口增加 `-e suite playback` 可检查播放器取流三态、640×360dp 布局与计时器清理。增加 `-e suite playback-real` 可执行真实播放回归：需要设备已有有效代理/授权及《魅影神捕》单集续播记录；会播放、拖动并上报正常进度，对失败处理入口注入受控失败后验证真实重试，不改加密连接设置或服务配置。真实回归仅在获准占用设备及播放媒体时执行。检查详情见[首次取流验收](../requirements/播放器首次取流验收.md)。
