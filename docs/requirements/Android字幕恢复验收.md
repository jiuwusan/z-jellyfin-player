# Android 字幕加载失败恢复

2026-11-23；Android 0.6.36（50），荣耀 BVL-AN00。仅 Android 实施，iOS 未实施。在 master 开发，本阶段按用户指示提交，不推送。

## 行为

- 只下载当前选中的 External 字幕；关闭字幕或视频已烧录时不附加独立字幕，其他轨的坏文件不会阻断播放。
- 独立文本完整下载后交给 Media3 解析。临时网络错误、408、429、5xx最多重试一次；重试重新下载完整正文，不拼接失败片段。单文件最多16MiB，超过后交给烧录兜底。
- 404/410先重新协商地址一次，再失败则尝试一次指定轨道烧录。解析失败直接尝试烧录；仍失败则关闭字幕继续视频。不存在字幕cue本身不触发错误或降级。
- 401/403/407直接关闭失败字幕，不反复请求或尝试烧录；重新协商API的鉴权错误保留相同语义。
- 恢复保持播放位置、暂停状态、音轨、画质和前后台状态。旧播放器回调在退出、切换或改变选择后不能接管新播放。
- 最终失败的轨道在字幕菜单标注“点击重试”，用户重新选择后可重置该轨预算。相同视频URL重建时复用会话，不重复上报开始或停止。
- 非字幕视频错误沿用播放器失败处理。仅明确的独立字幕加载或文字渲染错误触发字幕恢复；一次烧录新流失败可关闭失败字幕回到原视频。

## 验证方法

`subtitle-recovery` 检查恢复次数、HTTP状态、强制Encode协商、仅当前独立字幕、关闭字幕及正文中途断流的数据完整性。

`subtitle-recovery-real` 使用《魅影神捕》第2集，在客户端临时注入503、404、无效TTML、烧录协商失败和401。真实视频及烧录仍由现有Jellyfin提供，不修改服务、账号偏好或加密连接配置。每轮检查位置保持在180000ms附近、字幕恢复请求次数及退出后的旧回调。

本地证据保存于被忽略的 `verification/subtitle-recovery/`。测试过程中正常上报观看进度。未开放图片字幕本地解码，默认选轨仍由Jellyfin账号偏好决定。
