## 目标与范围

让家庭用户打开 App 后直接看到自己的媒体库和观看进度，能从海报找到电影或剧集，并在少量操作内开始播放或续播。页面全部由独立 Android 项目原生实现，媒体数据与观看记录来自 Jellyfin API。功能以家庭场景为准，无需覆盖官方 Jellyfin 的全部功能。

本期覆盖代理与授权、首页、媒体列表和媒体详情。沿用现有播放器、HTTP 代理、自动登录及 1080p／4 Mbps 转码规则。收藏、下载、投屏、服务器管理和多人账号快速切换留待后续。

## 1. 代理与授权

| 功能 | 需求 |
| --- | --- |
| 家庭代理 | 支持设置 HTTP 代理地址、端口、用户名和密码。代理用于 Jellyfin API、海报和视频流。沿用现有保存和连接验证机制。 |
| Jellyfin 授权 | 支持设置 Jellyfin 服务器地址、账号和密码。密码默认遮挡，敏感信息继续保存在当前 App 的加密存储中。 |
| 首次使用 | 从连接设置保存并成功登录后进入首页。代理连接失败、服务器不可用和账号验证失败应给出能区分的提示，允许重试或返回对应设置。 |
| 日常启动 | 配置有效时自动登录并打开首页。暂时取不到数据时显示重试入口，保留之前已验证的配置。用户可从首页主动打开连接设置。 |
| 升级保留 | 同包名、同签名覆盖安装后，已保存的代理和授权仍可使用。首次从旧验证包迁到新包需要重新配置。 |
| 播放画质 | 分辨率和码率上限使用 Jellyfin Web 档位，默认 1080p／4 Mbps。码率按音视频合计的编码预算计算。 |
| 保存确认 | 更新已保存的代理、授权或画质时，在点击「保存并连接」后弹出确认密码。取消或验证失败时保留上次成功保存的配置。 |

## 2. 首页

初版首页从上到下显示「继续观看」「接下来」「最近添加」；Android 0.6.22 起按上述更新移除「接下来」。顶部提供搜索和连接设置入口，媒体库从底部导航进入。电影和剧集使用海报卡片，横向浏览。卡片整块可点，标题最多两行，海报、文字和操作在不同屏幕宽度下保持可读。

| 区块 | 展示内容 | 点击行为 |
| --- | --- | --- |
| 继续观看 | 已开始且有可续播进度的电影和单集，按服务器返回顺序显示。每张卡片显示海报、片名或剧名与集号、进度条和已看位置，有时长时同时显示总时长。 | 点卡片任意位置，从服务端保存的位置直接续播，退出后回到首页。 |
| 接下来 | Jellyfin 为当前账号返回的下一集，使用剧集海报并显示剧名和季集号。已出现在「继续观看」的同一集在本栏跳过。 | 单集直接播放，电影和剧集进入对应详情。 |
| 最近添加 | 最近入库的电影、剧集和单集，沿用服务器返回顺序。按剧集聚合时，每部剧只占一张卡片。近期新增内容可以与其他区块同时出现。 | 单集直接播放，电影和剧集进入对应详情。 |

- 竖版卡片中的电影和剧集使用各自的主海报。首页「继续观看」和「接下来」的单集优先使用所属剧集的横版背景，取不到时依次尝试单集封面和剧集主海报。其他位置的单集优先使用自己的封面，缺失时使用所属剧集海报。缺图或取图失败时保留固定比例的占位和可点击标题。
- 续播进度以服务端的播放位置和总时长计算，比例限制在 0% 至 100%。缺少总时长时仅显示已看位置。退出播放并回到首页后，刷新相关观看状态。
- 三个区块独立加载。单个区块失败时在该处提供重试，已加载的区块继续可用。「继续观看」为空时显示简短说明，「接下来」和「最近添加」为空时可收起对应区块。
- 首屏优先显示区块和标题。海报按需加载并复用缓存，慢图或坏图不会阻塞选片与播放。

## 3. 媒体列表与详情

### 媒体列表

- 从底部「媒体库」进入。Android 0.6.30起移除「全部」，默认选中服务端返回的第一个可见视频媒体库。顶部横向标签均取自Jellyfin实际返回、当前账号可访问的视频媒体库；没有可见库时显示空状态。选择库标签后直接展示该库内容，使用响应式海报网格。iOS尚待同步。
- Android 列表使用服务端分页，每页 36 条，默认按条目添加时间倒序，同一添加时间按标题升序。添加时间采用 `DateCreated`，新增单集不保证将所属剧集置顶。上滑接近底部时自动加载下一页，并把新条目追加到当前列表。返回列表和切换标签时恢复此前的库、目录和浏览位置。媒体库和搜索中的单集直接播放，电影和剧集进入对应详情。
- Android电视剧库只查询 `Series`，电影库只查询 `Movie`，其他视频混合库查询 `Movie,Series,Video`；不发起额外的跨库「全部」混合查询，也不分查再合流。聚合结果完全采用Jellyfin服务端返回值，客户端不按名称、TMDB ID 或季集号额外合并、去重。
- Android 列表在顶部下拉可刷新当前标签。刷新期间保留旧列表，成功后从最新的第一页重新开始分页，其他标签的已加载数据和浏览位置保持。刷新失败保留旧列表并允许重试；加载或刷新期间避免重复请求。iOS 尚待实现该排序、类型查询及下拉刷新。
- 正常、加载中、空结果和加载失败均有对应状态。后续页失败时保留已加载内容，并允许重试。

### 媒体详情

Android 0.6.29 增加[合集适配](Android合集适配验收.md)：识别服务端返回的BoxSet及boxsets媒体库，合集页展示背景、封面、简介与成员网格；成员保持服务端顺序，不按添加时间重排。合集不直接播放，成员沿用原有详情或播放规则，保留刷新、分页、防误触及两层返回位置。iOS暂未实施。

Android 0.6.52 起，电影合集详情在封面右侧的播放区增加蓝色「播放」按钮。点击后完整读取直属成员的分页，按 Jellyfin 原顺序建立电影队列；不展开嵌套合集或剧集。起点为第一部未看完的电影，有进度续播，全部看完则从第一部开始。电影自然结束后按队列连续播放后续电影，保持横屏全屏；播放器提供上一部／下一部，最后一部自然结束返回合集并恢复竖屏。成员卡片原有详情行为保持不变，单独打开的电影仍按普通电影规则结束返回。准备期间按钮禁用，查询失败不使用部分队列，空合集提示暂无可播放电影；切流失败不自动跳片。现有代理、画质、音轨与字幕策略继续生效。iOS待实施。

Android 0.6.53 起，合集播放起点以本次查询返回的 Jellyfin `UserData.Played` 为准，不应用本地临时进度覆盖。第一部被服务端判定已看完、第二部有进度时，选择第二部并按服务端位置续播；不另加最近观看时间排序或客户端片尾阈值。首页、普通详情的临时进度补充规则不在本次修改范围。

| 对象 | 展示与操作 |
| --- | --- |
| 电影或普通视频 | 海报、片名、年份、时长和简介。没有保存进度时显示「播放」，有进度时显示「继续观看」和「从头播放」。 |
| 剧集 | 剧集海报、剧名、年份和简介。可选择季并浏览该季集数，集卡显示季集号、集名及已有观看状态。只有一季时直接展示集列表。点击集卡直接播放，退出后回到所选季。 |

资料缺失时省略对应字段，保留可用的播放操作。播放结束或退出后继续向 Jellyfin 上报进度。从详情返回首页时，续播和接下来区块反映更新后的状态。

## 4. 播放与设备验收

- 继续使用当前集成播放器。超出 **1920×1080** 的源视频由服务端缩放并输出 **H.264/AAC HLS**，保持宽高比例，音视频合计编码目标不超过 **4 Mbps**。符合尺寸的片源沿用现有协商流程。
- Android 点「播放」「继续观看」或「从头播放」默认进入横屏全屏播放器。视频按原始比例适配，点击画面可显示控制条和返回入口。退出播放恢复原来的屏幕方向设置和系统栏。
- Android 0.6.31起，首页、媒体库、详情、搜索和设置所在的主Activity默认固定竖屏；只有播放时切换为传感器横屏全屏，退出播放恢复竖屏和正常系统栏。沿用播放时左右横屏翻转能力，不修改用户的系统旋转设置。iOS尚未同步此规则。
- 单集直接打开播放器，有未看完的进度就续播，首次观看或已看完则从片头开始。
- Android 全屏播放器按[交互设计稿](../prototype/index.html?screen=player)布局。顶部显示片名、集名和轨道菜单，底部显示可拖动进度、播放时间、快退 5 秒、快进 15 秒和画质上限。展开控制区时字幕避开底部控件。
- Android 0.6.54 起按[中央五按钮设计](../prototype/large-type/全屏播放器新版设计.md)布局：上一集／部、后退5秒、播放／暂停、前进15秒、下一集／部居中排列，使用矢量图标与文字，普通电影隐藏两端切换入口。顶部为返回、片名和轨道入口，底部仅时间、画质及进度条。三块控制区一起按5秒规则显隐；暂停、缓冲、拖动、轨道菜单保持显示，缓冲时仍可暂停。原字幕字号、选轨、取流门控、失败重试、连播及结束返回规则保留。iOS待实施。
- Android 0.6.55 起，操作区按画面几何中心水平与垂直居中；安全区对称预留，不再将操作区上移或向一侧偏移。文字字幕固定保留底部工具栏区域，工具栏显隐时底部间距与字号不变；仅屏幕尺寸、安全区及布局尺寸变化时重新计算。烧录字幕不经过客户端文字布局。iOS待实施。
- Android 0.6.56 起，按用户确认取消字幕的工具栏占位，文字字幕恢复视频常规底部位置（默认底部间距按 Media3 默认值），保留字号与片源明确设置的位置；工具栏出现时允许进度区覆盖字幕，不再抬高字幕或随显隐跳动。

- Android 0.6.34起，设置的「首选的音频语言」「字幕语言偏好」读写当前 Jellyfin 账号配置。首次未连接的表单初值均为 Chinese；已有账号以服务端实际值为准，不在自动登录时覆盖为中文。保存语言偏好不要求确认密码，继续使用现有代理鉴权；更换或清除订阅仍要求确认密码。保留完整配置中的字幕模式和记忆选择等其他字段。自动播放采用 PlaybackInfo 的默认音轨、字幕索引，手动选择及关闭优先。读取偏好失败时语言项禁用，连接和画质仍可保存且不写账号语言。语言缓存仅用于草稿，不参与选轨；服务端区域码或未知语言保留原值。iOS待实施。
- Android 0.6.50起，「设置 → 播放」增加「优先播放默认音轨」，读取账号的 `PlayDefaultAudioTrack`，与两项语言偏好通过「保存播放偏好」一起保存，无需确认密码。开启时优先文件默认音轨，关闭后按首选语言选择，历史手动选择仍可能优先。读取失败时禁用，保存失败保留草稿可重试；不变更其他账号字段，Hub 不覆盖此项，不自动修改正在播放的音轨，从后续取流生效。iOS待实施。
- Android 0.6.35起，字幕按最终 PlaybackInfo 的 DeliveryMethod 分派：Embed 从内嵌轨选择，External 使用同源返回地址加载，Encode 走视频烧录。文本也可能被服务端指定 Encode，不能仅按编码分类；仅当响应缺少 DeliveryMethod 时保留旧接口兼容。独立字幕以影片完整时间轴加载，标准 Jellyfin 提取端点明确 start/end 为0、copyTimestamps=true、addVttTimeMap=false，保留其他返回参数并用请求头鉴权。未知投递方式、不可用地址或不支持的字幕不会伪造返回地址，菜单显示暂不可用。自动无字幕和手动关闭在直连、HLS均显式禁用文字轨。设备能力仍将图片字幕声明为烧录，未开放本地图片渲染；已有位置、暂停、音轨和画质恢复规则保持。
- Android 剧集全屏控制区提供「上一集」和「下一集」，按服务端顺序跨季切换可用单集。切换前记录当前进度，目标集有未完成进度时续播。电影隐藏切集入口，退出播放返回进入播放器前的页面。
- Android 当前集自然播完后自动播放下一集，保持横屏全屏。0.6.51 起，电影或确认没有下一集的剧集自然播完后，沿用手动返回流程结束会话、释放播放器，恢复竖屏并返回进入播放前的页面，保留浏览位置并更新观看进度。相邻集查询尚未完成、失败或结果未包含当前集时不自动退出；直接拖到片尾、片尾起播、暂停、后台、切轨中或播放失败仍停留在播放器，避免误退与重复返回。iOS 待实施。
- Android 全屏播放中 5 秒无操作时隐藏顶部和底部工具栏。暂停、缓冲、拖动进度条或打开字幕与音轨菜单时保持显示，操作结束并恢复正常播放后重新计时。

## API 对照

- **媒体库、列表与详情**：沿用现有 UserViews、Items、影片详情和主图 API。
- **继续观看**：沿用现有续播接口和 Jellyfin 的进度上报逻辑，以当前授权账号的数据为准。
- **接下来**：使用 Jellyfin 的 Next Up 接口，关闭可续播条目的返回选项，并核对与首页续播区块的重合项。[Jellyfin 10.11.11 Next Up 接口](https://github.com/jellyfin/jellyfin/blob/v10.11.11/Jellyfin.Api/Controllers/TvShowsController.cs#L72)
- **最近添加**：使用 Jellyfin 的 Latest Media 接口，沿用服务端返回的排序及当前账号的显示设置。[Jellyfin 10.11.11 Latest Media 接口](https://github.com/jellyfin/jellyfin/blob/v10.11.11/Jellyfin.Api/Controllers/UserLibraryController.cs#L487)

## Android 页面返回恢复（0.6.40）

- 首页、详情、季集列表在当前登录会话内复用已加载数据；媒体库底部导航保留当前库、分页和浏览位置。搜索沿用已有的结果和位置恢复。
- 普通返回使用已有内容，不重复显示首次加载骨架屏。首次无缓存、缓存被回收或进程重启仍走首次加载流程。
- 播放退出立即更新本地进度，后台查询排在停止上报之后。同步期间保留画面；上报失败时保留本地进度，查询成功且停止上报已确认后以服务端结果校准。
- 首页下拉刷新保持原有交互，失败保留内容并提供重试。未变化的首页内容不重建卡片。
- 页面数据缓存最多 40 个条目、浏览位置最多 40 项；非当前媒体库最多保留 3 个库及合计 1500 个条目，超限按近期使用情况回收。当前正在浏览的分页列表不截断；被回收的库再次进入需重新加载。
- 首页超过两分钟后返回会后台同步；详情超过十分钟后返回先展示缓存并后台更新详情缓存，下次进入使用更新结果。重新连接授权清空全部会话数据，不写入磁盘。
- 浏览保持竖屏，播放退出立即恢复内容时使用保存的竖屏宽度，避免横竖屏配置尚未更新导致卡片被拉高。
- Android 本轮实施；iOS 暂未实施。

## Android 图片加载（0.6.41）

- Android 0.6.57 起，媒体库和合集成员列表按可见区域回收复用卡片；合集顶部详情、分区标题和成员卡片共用一个滚动区域。保持原有服务端顺序、分页、下拉刷新及滑动防误触；返回时按条目与偏移恢复位置，分页新增上方分区也保持当前内容的位置。
- 卡片换绑或回收时释放原图片绑定并清除 Drawable；旧请求不得覆盖新条目，重新进入可同步复用内存缓存。已开始的共享图片请求可完成并进入缓存，无等待者的排队任务取消。本次不调整解码尺寸、缓存键及缓存预算，也不增加磁盘缓存。iOS 暂未实施。

- 首页、媒体库、合集、搜索、详情、单集缩略图和播放器取流背景统一使用 `ArtworkLoader`；只加载可见区域及约 100dp 的相邻区域，滚动后继续按需加载。
- 缓存命中同步显示，不执行网络图片淡入；相同资源请求合并，未开始的离屏请求取消。页面仍可重建，已缓存海报无需重复下载。
- 小图和详情大图分别使用有界内存缓存，每块按设备内存等级的八分之一计算，最少 2 MiB、最多 24 MiB。超过单块容量的图片不挤占已有缓存。
- 详情图请求不增加服务器宽度上限；下载后在手机按实际展示尺寸采样解码。共享剧集背景和各单集备用图使用独立请求与缓存键，不混用备用图片。
- 图片版本标签进入缓存键，以便服务端图片变更后使用新资源。重新连接授权清空缓存，旧连接的迟到结果不写入当前页面或缓存。
- 没有引入磁盘缓存；进程重启、缓存回收后允许重新请求图片。Android 本轮实施，iOS 暂未实施。

## Android 本地界面模式（0.6.59）

设置 → 播放增加「长辈模式」开关。未设置时默认标准模式；开启后使用大字版。偏好仅保存在当前设备，不随订阅同步，不修改 Jellyfin 语言、轨道或画质设置。

两种模式共用 API、数据缓存、分页、图片加载和播放流程。标准版采用常规字号、手机三列海报、紧凑导航与图标工具栏；详情仍保留横版背景、渐变和封面。首页点击规则和滑动防误触保持一致。切换后保留媒体库、设置 Tab 和当前可见媒体；处于页面顶部时仍从标题开始显示。重启保留模式，但会话数据仍按现有冷启动流程加载。

播放器只调整控件尺寸，保留字幕绘制大小与位置、音轨和字幕切换、上下集／部、自动连播、五秒自动隐藏。Android 已实现，iOS 本轮不实现。验收见 [标准版 UI 验收](Android标准版UI验收.md)。

## Android 首页模块（0.6.60）

标准模式首页按顺序展示继续观看、接下来和最近添加，每个模块横向滑动，页面整体上下滚动，空模块隐藏。继续观看为大横卡，接下来为紧凑横卡，最近添加为竖版海报。横向列表按可见区域回收卡片，返回时恢复媒体条目和偏移；冷启动重新获取列表。

长辈模式只显示一个纵向大卡片列表：优先继续观看，空时接下来，再为空时最近添加；三者都空才展示空状态及前往媒体库入口。最近添加不展示虚构时长或进度。

继续观看和接下来的播放图标触发播放／续播，卡片主体进入详情；单集卡片进入所属剧集详情。最近添加在两种模式都不提供播放图标，电影、剧集和单集均只进入相应详情，合集进入成员列表。保留横向与纵向滑动防误触。

三个模块共用现有连接、API 和同一轮会话缓存。切换界面模式不重新查询；下拉刷新更新完整快照，网络错误不当作空列表，不因失败错误切换兜底，保留已有内容并提供重试。停止上报和本地观看进度的处理顺序不变。Android 本轮实现，iOS 未实施。

## 最近添加海报（Android 0.6.61）

标准模式最近添加采用竖版海报：电影、剧集和合集使用条目自身 Primary；单集优先使用列表已有 SeriesId 对应的剧集 Primary，不再优先把单集截图裁成竖图。列表已有 SeriesPrimaryImageTag 时用于缓存版本；同一剧集的单集共享海报缓存。不增加媒体详情查询，仅请求图片。

剧集海报缺失时，可回退到单集自身主图；单集缺少 SeriesId 时继续使用自身主图。接下来、继续观看以及长辈模式的横版背景优先级保持原样。代理、订阅、画质和卡片点击规则不变。iOS 本轮未实施。

## 字号策略（Android 0.6.62）

App 页面、输入框、下拉选项、对话框与播放器控件使用 App 规定的字号，不再跟随系统字体大小。标准模式和长辈模式仍分别使用各自的字号及控件规格。手机显示密度、屏幕方向、尺寸和语言不由此策略固定；字幕继续沿用既有绘制规则，服务端烧录字幕不受客户端设置影响。

实现使用 Activity 原生 applyOverrideConfiguration，在首次读取界面资源前仅覆盖 fontScale=1。不修改系统字体设置，不调用全局 Resources.updateConfiguration。系统键盘、权限弹窗等外部系统界面仍由系统控制。Android 已实现，iOS 本轮未改动。
