# z-jellyfin-hub 技术方案

日期：2026-11-24。状态：Hub 与 Android 首版已实现并本地验证；镜像发布、NAS 部署和生产 HTTPS 订阅联调待执行。实现差异与验证范围见 [实施验收记录](../acceptance/2026-11-24-首版验收.md)。

已确认：服务端项目名 `z-jellyfin-hub`；每位使用者独立订阅，同一人的多台设备可复用；手机只填写订阅链接；字幕与音轨继续由使用者控制，其他现有可配置项统一下发。

服务端规范、需求、协议和部署文档分别归入 Hub 的 `docs/standards`、`docs/requirements`、`docs/api`、`docs/deployment`，客户端保留接入需求与协议副本。Android 已实施订阅接入；iOS 本轮仅交接归档；现有服务配置未修改。

## 1. 使用方式与职责

管理员在网页后台维护代理、Jellyfin 授权、播放策略，并给每位使用者生成一个订阅链接。手机首次输入链接后获取配置，验证代理与 Jellyfin 登录，成功后保存并进入首页。以后打开 App 自动连接。

| 项目 | 管理来源 |
| --- | --- |
| HTTP 代理地址、端口、用户名、密码 | Hub |
| Jellyfin 地址、用户名、密码 | Hub |
| 分辨率上限、音视频合计码率上限 | Hub |
| 订阅刷新间隔、客户端兼容性要求 | Hub |
| 首选音频语言、字幕语言偏好 | 沿用 App 读写 Jellyfin 账号偏好的现有实现 |
| 播放时音轨、字幕选择与关闭 | 手机端，沿用现有实现 |
| 订阅链接 | 手机首次填写；更换时保留防误操作确认 |

“其他都下发”在第一版覆盖现有用户可配置项，不包含远程执行代码、任意覆盖 App 内部参数或修改 Jellyfin Server 配置。H.264/AAC 转码、硬解选择、字幕投递兼容规则、列表点击和滑动防误触继续由客户端代码维护。

Hub 负责管理和下发配置，媒体请求仍走当前家庭 HTTP 代理直达 Jellyfin。Hub 不转发视频，不接管播放会话，也不持有 Jellyfin 管理员 API Key。

同一人的多台设备共用 Jellyfin 账号时，首选音频语言和字幕语言偏好仍按 Jellyfin 的账号级设置同步；播放中手动选轨/关闭字幕保持当前播放会话的行为。如需改为每台手机独立保存语言偏好，应作为单独的需求调整，不在订阅接入时默默改变。

## 2. 架构与技术选型

推荐单容器提供管理后台和配置接口：

```text
管理员浏览器 ── HTTPS ── z-jellyfin-hub
                         ├─ 管理页面和管理 API
                         ├─ 订阅配置 API
                         └─ SQLite 与加密凭据

手机 App ── 直连 HTTPS ── Hub：获取配置
手机 App ── 下发的 HTTP 代理 ── Jellyfin：登录、媒体、播放
```

| 层级 | 推荐 | 选择理由 |
| --- | --- | --- |
| 后端 | Go，标准库 HTTP 路由和服务 | 接口规模小，便于单进程部署 |
| 管理后台 | Vue 3、TypeScript、Vite | 表单、配置关联和版本预览可独立维护 |
| 数据库 | SQLite | 单实例、少量管理写入，无需独立数据库容器 |
| 前端交付 | 构建产物通过 Go embed 打包 | 容器运行时不需要 Node.js |
| 部署 | Docker Compose，提供 amd64/arm64 镜像 | 适配 NAS 与普通 Linux 主机 |
| TLS | 已有 HTTPS 入口或独立反向代理 | App 严格验证系统信任的证书 |

Go embed 可将静态资源编译进程序；Vue 官方提供 TypeScript/Vite 工程支持。SQLite 适合本方案的单实例读多写少场景，第一版不设计多副本共享数据库。[Go embed](https://pkg.go.dev/embed)、[Vue TypeScript](https://vuejs.org/guide/typescript/overview)、[SQLite WAL](https://www.sqlite.org/wal.html)。具体依赖与工具链版本在开始实施时锁定，不在方案阶段使用浮动版本。

替代方案：静态 JSON 可以验证订阅流程，但无法方便地管理个人授权、停用、轮换和历史版本；前后端与数据库分成多个容器适合更大规模，目前增加部署维护量。第一版采用上述单容器方案。

## 3. 后台业务模型

采用共享模板与个人授权组合，避免复制大量相同配置。

| 实体 | 内容 |
| --- | --- |
| 代理配置 | 名称、HTTP 地址与端口、可选认证凭据 |
| Jellyfin 服务 | 名称、基础地址，允许包含 `/jellyfin` 等路径前缀 |
| Jellyfin 授权 | 所属服务、用户名、加密密码 |
| 播放策略 | 分辨率枚举、合计码率；默认 1080p / 4 Mbps |
| 订阅 | 使用者名称、代理/授权/策略引用、状态、令牌摘要、配置版本 |
| 发布版本 | 订阅最终配置的不可变快照、发布时间、变更说明 |
| 应用反馈 | 最近检查时间、平台、App 版本、已应用版本与脱敏错误类别 |

多位使用者可共用代理与播放策略，各自绑定 Jellyfin 授权；需要时也可使用不同代理。共享模板变更必须预览受影响订阅，再显式发布。草稿保存不影响手机。

后台第一版页面：登录、代理配置、Jellyfin 服务与授权、播放策略、订阅列表、订阅详情与发布历史。订阅详情提供生成/轮换链接、停用、重新启用、发布预览和回滚。

发布在数据库事务内生成完整快照。回滚旧内容时创建一个更高的新版本，不将版本号倒退。反馈只显示“最近报告”，不据此宣称设备当前在线；第一版不做强制设备绑定或设备数量限制。

## 4. 订阅链接与协议

### 4.1 链接

推荐链接格式：

```text
https://hub.example.com/api/v1/subscription/config#SECRET
```

App 提取 fragment 中的 SECRET，去掉 fragment 后请求该 HTTPS 地址，将 SECRET 放入 `Authorization: Bearer`。fragment 不作为 HTTP 请求路径或查询参数发送，减少反向代理访问日志泄漏完整凭据的机会。后台、App 仍不得记录完整链接或认证头。

链接不含订阅 ID，SECRET 唯一绑定订阅；内部 ID 只用于数据库关联。默认生成 32 随机字节的规范 Base64URL 令牌（43 字符），支持手动指定和恢复备份令牌。服务仅保存摘要，通过唯一索引禁止重复绑定，拒绝含空白/CRLF/非规范尾位的输入；完整链接只在创建/设置时展示，需另行备份。令牌轮换与配置版本更新是两项独立操作。

订阅请求使用独立网络客户端，显式直连，不使用下发代理、不附带 Jellyfin 或代理认证头、不共享 Jellyfin Cookie。保留 URL 路径前缀；禁止 HTTP 降级、跳过证书校验及自动跨站重定向。第一版可直接禁止订阅接口重定向。

### 4.2 配置示例

以下均为占位内容，不是生产凭据：

```json
{
  "schemaVersion": 2,
  "serverInstanceId": "11111111111111111111111111111111",
  "subscriptionId": "0123456789abcdef0123456789abcdef",
  "revision": 12,
  "minClientVersionCode": 57,
  "refreshIntervalSeconds": 900,
  "connection": {
    "proxy": {
      "type": "http",
      "host": "proxy.example.com",
      "port": 8080,
      "username": "PROXY_USER",
      "password": "PROXY_PASSWORD"
    },
    "jellyfin": {
      "baseUrl": "http://jellyfin.internal:8096/jellyfin",
      "username": "JELLYFIN_USER",
      "password": "JELLYFIN_PASSWORD"
    }
  },
  "playback": {
    "resolution": "1080p",
    "totalBitrateBps": 4000000
  }
}
```

schema v2 从 Android 0.6.43 / 57 支持；v1 仅保留作设备内已有加密缓存的迁移来源，网络使用 v2。第一版只下发现有 HTTP 代理方式，代理用户名/密码可按现有方式留空；Jellyfin 授权仍使用个人账号密码，沿用现有自动登录。

分辨率支持 `auto`、`screen`、`360p`、`480p`、`720p`、`1080p`、`4k`、`8k`。合计码率保留当前客户端支持的选项，`0` 表示自动。服务端与 App 都严格校验枚举、端口、地址、字段类型和必要字段，不将非法远程值默默替换成默认值。

协议不下发音频/字幕语言或轨道索引，也不下发 Jellyfin 管理员权限或证书校验开关。客户端只识别白名单字段，未知可选字段忽略；不支持的 schemaVersion 或必要能力导致整份候选配置被拒绝，已有配置不被覆盖。

### 4.3 接口与缓存语义

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/subscription/config` | 获取经过鉴权的完整配置；支持 ETag / If-None-Match |
| `POST /api/v1/subscription/feedback` | 上报已应用版本或错误类别；使用订阅令牌鉴权 |
| `/api/v1/admin/...` | 后台登录、模板与授权管理、订阅及发布管理 |
| `GET /health/live`、`GET /health/ready` | 容器健康检查，不返回凭据或配置 |

配置接口先鉴权及检查订阅状态，再处理 ETag；停用或无效令牌不能收到 304。ETag 对应最终有效配置快照，模板或凭据变化必须生成新 revision，避免客户端漏更新。

成功返回 200，未变化返回 304；令牌无效返回 401，订阅停用返回结构化 410，限流返回 429，临时故障返回 5xx。未找到订阅按认证失败处理，不泄漏账号信息。错误正文使用稳定业务错误码，不返回密码、认证头或包含秘密的地址。

订阅响应禁止共享缓存/CDN 缓存，设置私有且需重新验证的缓存策略；代理访问日志不记录认证头。App 不使用通用 HTTP 磁盘缓存保存配置，而是显式加密保存已验证业务配置。

## 5. Android 配置生命周期

版本序列按 serverInstanceId + subscriptionId 划分，同来源禁止回退和同版本改内容；不同来源必须重新验证代理/Jellyfin，成功后可接受版本 1。实例标识随数据库持久化，重启/完整备份保留，新数据库产生新标识；ETag 包含实例/订阅/版本。灾后在原 HTTPS 入口重建配置并绑定原令牌、发布，设备原链接无需重新填写。已验证旧缓存自动迁移固定链接、清旧 ETag，随后刷新，不恢复旧版手动设置入口。

### 5.1 首次导入

1. 输入订阅链接，解析并校验 HTTPS、固定订阅路径及 SECRET。
2. 直连 Hub 获取候选配置，总请求超时建议 8 秒，响应体限制建议 64 KiB。
3. 校验协议版本、App 兼容性、字段与现有画质选项，验证对应 HTTP 代理和 Jellyfin 登录。
4. 全部成功后原子保存订阅信息与“最后一次可用配置”，进入首页。
5. 下载成功但登录失败时保留候选状态和明确错误，不能把它替换为可用配置。首次无可用配置则停留在连接页，提供重试和更换链接。

### 5.2 日常打开与刷新

- 已有可用配置时立即按缓存连接，后台检查订阅，不等待 Hub 后才展示首页。
- 默认前台每 15 分钟检查一次，可由 Hub 下发；App 对间隔施加合理上下限，例如 5 分钟至 24 小时，并增加少量随机抖动。
- App 回到前台时仅在超过检查间隔后刷新。第一版不依赖常驻后台服务或精确后台定时任务。
- 304 不重新登录、不清理媒体与图片缓存、不重建页面。失败按退避重试，不连续弹窗。
- 网络断开、DNS、TLS 或 5xx 等故障继续使用最后可用配置，设置页显示最近同步时间和状态。第一版不设置额外的离线使用期限。
- 收到明确的无效令牌或停用响应时，不再用缓存建立新的登录或播放连接；当前播放结束后转为需要更新订阅状态，避免突然打断老人观看。
- 更换链接失败时不替换旧有效订阅；候选数据与旧缓存始终分开，避免串用不同人的账号。

### 5.3 应用变更

| 变更类别 | 应用方式 |
| --- | --- |
| 无变化 | 不做连接或页面操作 |
| 仅刷新间隔 | 更新订阅调度 |
| 仅分辨率、码率 | 下次开始播放生效，当前流与字幕/音轨保持不变 |
| 代理、Jellyfin 地址或授权 | 先验证新连接；正在播放时暂存，退出后再切换 |
| Jellyfin 服务或账号变更 | 切换成功后清理旧账号的浏览、图片、字幕缓存及会话，使用新账号自己的语言偏好 |
| 同账号重新连接 | 不覆盖其 Jellyfin 音轨/字幕偏好；按既有连接隔离规则处理缓存 |

切换前完成旧会话停止上报，再替换连接；每个候选配置带版本和请求代次，旧请求不能写回新账号页面。服务端如果同时立即撤销旧代理/Jellyfin 凭据，旧流仍可能被上游中断，客户端延后应用不能保证这类更改无中断。

## 6. 手机设置页

最终保留：订阅链接（默认掩码）、订阅状态、上次同步时间、手动同步、首选音频语言、字幕语言偏好，以及 App 版本。代理、服务器地址、账号密码、画质改为受管理信息，不再提供本地编辑入口，密码不显示。

更换或清除订阅沿用预设确认密码 `jellyfin`，用于防误操作。它不作为 Hub 管理员密码或订阅鉴权手段。普通手动同步不需要确认密码，不改动字幕/音轨偏好。

所有安装统一使用订阅入口，不保留旧手动连接配置页面，也不在启动时读取旧配置回退登录。未填写订阅或订阅缓存不可用时进入订阅设置；仅可使用最后验证成功且未被停用的订阅缓存。清除订阅后回到订阅设置。

## 7. 服务端数据与凭据

- Hub 管理员使用独立账号密码，首次启动设定，不能使用 App 的固定确认密码。登录密码使用成熟密码哈希实现；管理会话使用 HttpOnly、SameSite Cookie，浏览器 HTTPS 时添加 Secure，管理写操作做 CSRF 防护与登录限流。
- Jellyfin/代理密码必须能解密下发，不能只做密码哈希；使用带随机 nonce 的 AES-GCM 加密，绑定记录标识和字段类型作为附加认证数据。主密钥首次自动生成到独立 secrets 卷（0600），不放镜像、数据库或 Git；已有数据库缺少原密钥拒绝启动。
- 订阅 SECRET 只存摘要，完整链接、密码、Jellyfin token、配置响应正文均不进入日志。后台密码字段默认掩码，未输入新值时保留旧值。
- 手机沿用 Android Keystore 加密，但订阅秘密、候选配置和最后可用配置要与字幕/音轨偏好分开管理。发布版本快照中的敏感字段同样加密。
- 配置导入导出和备份默认不明文导出凭据。SQLite 使用一致性备份接口，主密钥另行保管，恢复测试同时核对数据库与密钥，不能只复制运行中的主数据库文件。[SQLite 备份](https://www.sqlite.org/backup.html)、[Go GCM](https://pkg.go.dev/crypto/cipher)。

停用/轮换订阅只能阻止后续配置获取以及守规客户端的新连接，不能撤销已经取得的 Jellyfin 凭据或登录令牌。若链接或凭据泄漏，管理员还需在对应服务轮换密码或撤销会话；Hub 第一版不自动调用 Jellyfin 管理接口处理撤权。

## 8. 部署建议

Compose environment 仅设置 TZ=Asia/Shanghai，不填写 HUB_PUBLIC_URL。首次网页引导通过容器命令获取的一次性码创建管理员，不预置管理员密码文件。订阅 API 生成相对路径，由浏览器当前地址生成完整链接，支持路径前缀。

优先部署到可从异地直达 HTTPS 的主机。可以使用 NAS Docker，也可使用独立云主机；首版按 NAS 单实例设计。订阅响应很小，Hub 线路不承担媒体吞吐。

容器只提供内部 HTTP 服务，例如容器内 8097/TCP，由 HTTPS 入口转发；数据库和密钥位于两个独立本地持久化卷。后台不限制域名、IP、端口或 HTTP/HTTPS，保留 CSRF 和会话保护，不设置固定 Origin 白名单；Android 订阅仍要求 HTTPS。SQLite WAL 放在本地主机存储，不按多实例/NFS 共享库部署。

部署时新增 Hub 容器和所需 HTTPS 路由即可，Jellyfin、mihomo 的现有配置无需改变。新增 HTTPS 路由、域名证书和主机端口映射属于实施阶段工作，本方案不执行这些变更。

建议工程结构：

```text
z-jellyfin-hub/
  cmd/hub/
  internal/auth/
  internal/subscription/
  internal/configuration/
  internal/storage/
  internal/secret/
  web/
  migrations/
  deploy/
  docs/standards/
  docs/requirements/
  docs/api/
  docs/deployment/
```

## 9. 客户端改造落点

| 文件或模块 | 计划改动 |
| --- | --- |
| 新增 SubscriptionSettings | 订阅 URL、秘密和同步状态的加密存储；不记录完整 URL |
| 新增 SubscriptionClient | 独立直连 HTTPS、鉴权、ETag、超时和响应校验 |
| 新增 ManagedConfiguration | 严格解析远程字段，映射现有代理与画质选项 |
| 新增 ConfigurationApplier | 候选验证、版本判断、播放中延后应用、原子提交和失败保留 |
| ConnectionSettings.java | 从受管理配置生成运行配置，解耦语言偏好；不读取旧手动配置 |
| MainActivity.java | 简化设置页、启动时使用已验证缓存、前台同步与连接切换 |
| JellyfinApi.java | 沿用登录与代理传输；字幕/音轨账号偏好接口保持现有语义 |
| PlaybackPolicy.java | 沿用现有分辨率与码率映射，远程值进入前先严格校验 |

iOS 共用协议和验收规则，凭据使用 Keychain；本轮先设计 Android 接入，不宣称 iOS 已实现。

## 10. 实施阶段与验收

1. **协议与服务端最小闭环**：建立 Hub 仓库规范、协议样例和迁移；完成管理员登录、模板、个人订阅、完整快照、HTTPS 联调。
2. **Android 订阅接入**：验证单链接配置、代理/API/图片/视频全链路、订阅账号自动登录、最后可用订阅缓存与旧入口移除。
3. **后台管理与更新闭环**：完成发布预览、共享模板影响范围、版本回滚、停用与令牌轮换；完成配置更新时机和状态反馈。
4. **发布验收**：生产签名、覆盖升级路径、数据库/密钥备份恢复、日志脱敏；在荣耀与红米验证实际硬解、字幕、音轨与续播。

必须覆盖：两个人的订阅互不串号；同人两设备可使用；Hub 离线且媒体服务可达时仍可按缓存播放；错误配置不替换有效配置；304 不重新登录或加载页面；画质更新不打断当前播放；切换账号清理旧数据；订阅停用与凭据撤权的边界明确；代理改变后 API、海报和视频均走新代理；字幕与音轨偏好未被 Hub 覆盖。

本方案推荐 Go + Vue 3 + SQLite、每人独立订阅、前台轮询和个人 Jellyfin 账号密码下发。技术栈及界面细节仍可在实施前调整，未作代码或服务变更。
