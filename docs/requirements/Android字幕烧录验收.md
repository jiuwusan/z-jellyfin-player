# Android 字幕投递与图片烧录

日期：2026-11-23。Android 0.6.32（46），荣耀 BVL-AN00；iOS 未实施。沿用原包名、签名、代理、授权和画质配置，不修改 Jellyfin 配置、媒体文件或元数据。

## 原因与处理

《人类清除计划2》有三个 PGS 图片字幕轨，默认轨索引 4 为中文字幕。旧实现过滤图片字幕，HLS 又固定传 SubtitleStreamIndex=-1，所以没有字幕。现在保留图片轨并在自动模式遵循服务端默认选择。

- 文本字幕仍由 Media3 加载和绘制，使用既有代理和鉴权。
- 图片字幕在 PlaybackInfo 和 HLS 请求中明确指定索引及 Encode，强制视频编码，由 Jellyfin 烧录到画面；手机文字轨关闭，避免双字幕。
- 关闭字幕显式传 -1 并移除烧录参数；切回文本也关闭服务端烧录。
- 图片轨改变时重新取流，复用现有切换恢复流程，保留位置、暂停状态、片源、音轨和画质；音轨切换反向保留字幕偏好。关闭状态在换集时延续，其余模式按新集默认轨选择。
- 失败保留原播放器或回滚原流；过时回调不能接管当前页面。

## 检查入口

构建主 APK 和 androidTest APK，设备保存有效连接后，通过现有 LoadingTransitionCheck instrumentation 入口运行：

| suite | 范围 |
| --- | --- |
| subtitles | 设备环回 HTTP fixture，覆盖默认 PGS、文本、关闭、不同音轨、质量预算、禁止双字幕；不限画质时文本/关闭可直连，图片仍强制转码 |
| subtitles-real | 《人类清除计划2》默认中文 PGS、切英文图片轨、关闭、恢复自动，暂停与位置保持；再检查真实文本片源 |
| subtitles-text | 只执行《魅影神捕》文本字幕手机绘制检查，取 3 分钟处对白并等待实际 cue |
| playback-real | 既有真实播放、首帧、重试续播、横屏全屏、返回竖屏和设置不变检查 |

真实播放检查会正常上报进度，不会修改加密连接设置。截图由设备 UiAutomation 产生，具体片源未包含在工程或测试安装包中。测试包不包含连接凭据。

## 已核验结果

- 旧实现受控检查先以“PGS subtitle was filtered out”失败；修复后请求检查 ALL_PASS。
- 《人类清除计划2》默认轨 4 的繁体中文已在荣耀截图中可见，硬件解码器 c2.qti.avc.decoder，接收 H.264。画质保留 MaxWidth=1920、MaxHeight=1080，视频 3,808,000 + 音频 192,000 bps 编码预算。真实首帧采样为 960×400，属于上限内，并非固定输出 1080p。
- 第一轮切英文图片轨、关闭及恢复自动均保持 606340 ms，原暂停状态及音轨索引 1 保留。字幕菜单支持这些保留的图片轨；切换通过同一生产回调处理。
- 最终 subtitles-real 整轮 ALL_PASS；增加暂停拖动至 600000 ms 后，再切英文图片轨、关闭、恢复自动，三次位置均为 600000 ms。恢复播放正常；真实文本 cue 与连接设置不变检查一并通过。
- 文本片源《魅影神捕》第 2 集明确选择文本轨，收到实际文字 cue 并截图，未请求烧录。一次片头 1 分钟检查未收到 cue，后改用 3 分钟对白通过。
- 既有 playback-real 回归 ALL_PASS：自动登录、硬解首帧、重试续播、横屏全屏及退出恢复竖屏。加密连接设置逐字节不变。

本地证据在被忽略的 verification/subtitle-fix。主 APK 复制到系统下载目录；设备端临时截图和专用测试包交付前清理，主 App 及原配置保留。

## 限制

当前真实电影只有一个音轨，多音轨索引保留由 fixture 验证；未覆盖所有图片字幕编码、所有服务端转码器或整片长时间播放。图片字幕成为视频内容，字号、位置取决于源字幕和服务端烧录，不受手机文本字幕样式控制。烧录会增加服务端转码开销。

本轮没有声称全量 Lint 通过；此前已有 DisplayCutout NewApi 错误，未修改无关代码。
