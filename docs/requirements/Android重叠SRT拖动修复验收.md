# Android 重叠SRT拖动修复

2026-11-23，Android 0.6.39（53），荣耀 BVL-AN00。当前master实施，用户确认后修复；按用户指示提交并推送。仅Android实施，iOS未实施。

## 原因与边界

Media3 1.8.0拖动后清空文字渲染缓存，内嵌字幕样本队列按开始时间定位最近一条，丢失更早开始但仍有效的字幕。SRT解析器本身已启用重叠合并；仅改合并开关或仅改独立文件不够。

本轮修复App实际协商/播放路径，不修改Media3源码。`subtitle-compat`中故意返回Embed的诊断仍可复现底层限制，不把该结果声称为已修复。新增`srt-seek`让受控服务端按客户端声明提供独立SRT，再用同一物理MKV、同一字幕内容验证。

## 实现

- 能力声明仅移除srt/subrip的Embed，保留External；TTML和其他格式保持既有策略。读取服务端实际返回的DeliveryUrl，不改服务配置或媒体文件。
- 完整SRT解析成按起止边界排序、互不重叠的显示区间，每个区间包含全部有效字幕；结束时间采用半开区间，不重复显示到下一段。
- 默认位置的同时有效文字合为多行，保留原文本span与顺序，不按文字去重；有定位的cue保留原定位。沿用透明底、描边与工具栏上移处理，不新增字号设置。
- 末尾补空cue结束标记。Media3 1.8以最后样本开始时间估算未知时长，缺少此标记会截短最后一个有效区间；该标记保证拖动到末条字幕中间仍可显示，结束后正常清空。
- 沿用缓存原始字幕、HTTP代理、Authorization头、手动选轨、暂停与画质；只有SRT使用新解析工厂。
- 限制20000输入条目、128条同时有效cue、200000输出引用和800万累计文本字符；超预算进入已有解析失败/一次烧录兜底，不无限增长内存。

## 已保留的限制

首次提取/下载完整字幕可能需要等待，后续可使用当前连接内存缓存。复杂ASS特效、PGS图片大小、本地图片字幕渲染不在本轮范围。强制忽略能力声明返回Embed的服务、其他机型及全部片源未穷举。

## 复现入口

使用 `android/verification-src/prepare-subtitle-compat.ps1` 准备原官方Media3小样本；`srt-timeline`执行有界区间/协议检查，`srt-seek`执行应用兼容路径，`subtitle-compat`保留底层Embed诊断。参考[原兼容性补验](Android字幕缓存与兼容性验收.md)。
