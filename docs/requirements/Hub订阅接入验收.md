# Hub 订阅接入与跨端交接

共享需求：[技术方案](z-jellyfin-hub技术方案.md)。接口正文：[订阅协议](../api/订阅协议.md)，[Schema](../api/subscription-v2.schema.json)，[虚构样例](../api/subscription-v2.example.json)。服务端与网页管理后台位于同级仓库 z-jellyfin-hub；实现验收见该仓库 docs/acceptance/2026-11-24-首版验收.md。

## 范围

| 工程 | 本轮工作 | 联调与验收 |
| --- | --- | --- |
| Hub / Web | 实现管理、加密存储和下发；Docker/Actions 文件 | 本地 Go、前端和浏览器已验证；生产 HTTPS、镜像、NAS 待验证 |
| 原生 Android | 已实现个人 HTTPS 订阅，版本 0.6.43 | 荣耀受控订阅与既有真实硬解回归通过；真实部署订阅待联调 |
| 原生 iOS | 需求和协议交接，未实现 | 后续需独立实现 Keychain、URLSession、播放器代理和应用时机；本轮不宣称支持 |
| uni-app | 当前项目无此工程 | 不涉及实现或联调 |

首次保存、更换和清除订阅要求确认密码 jellyfin；手动同步不要求。不保留旧版手动设置入口和启动回退；未配置有效订阅时进入订阅设置，清除后也回到订阅设置。字幕/音轨及语言偏好继续沿用 Jellyfin 账号设置。

## 上线联合验收清单

- [ ] 配置正式 HTTPS Hub、有效系统证书和管理员，生成每人独立链接；多台设备可使用同一人的链接。
- [ ] 新安装只填写链接，即可经下发代理登录并浏览/播放；UI 不展示秘密，日志不出现完整链接或密码。
- [ ] 200、304、离线、错误凭据、错误协议版本和损坏缓存；旧成功配置不被失败候选覆盖。
- [ ] 播放时发布连接变化：旧会话不中途重建，退出后应用；画质变化从下一次新取流生效。
- [ ] 失效/停用先鉴权再比较 ETag；不新建播放/切集；重新启用并验证后恢复。
- [ ] 修改草稿不生效、发布生效、回滚产生更高版本、轮换旧链接失效。
- [ ] 代理、自动登录、分辨率/码率、字幕/音轨和进度切换回归；荣耀/红米硬解状态分别监控。
- [ ] 页面缓存、续播位置和滑动防误触保持；测试退出后无测试账号/代理残留。

协议副本应与 Hub 同名文件逐字节一致；同步规则与哈希见 [归档核验](Hub订阅归档核验.md)。Android/iOS 子目录各保留本地交接入口。

## v2 令牌恢复补充清单

固定链接 /api/v1/subscription/config#TOKEN，Bearer 摘要定位订阅。新建可指定原令牌，已有订阅可手动设置或随机轮换，令牌需另行备份。Go/Web 验证重复或非法输入不改变原绑定、旧令牌失效、原令牌恢复后链接不变、服务重建不同实例/内部 ID 的响应不误返回 304。

- [x] Android 0.6.43 自动迁移已验证的 v1 加密缓存/旧链接，不重新输入；网络拒绝 v1。
- [x] 同实例/内部订阅 ID 防回退和同版本改内容，换 URL 仍执行；新来源必须重验证成功才允许版本 1。
- [x] 停用状态下恢复原令牌并重建服务后可自动重新应用；验证失败保留原缓存。
- [x] 新来源重新获得的 JellyfinApi 不因凭据相同而被丢弃；播放期间延后应用。
- [ ] 正式 HTTPS Hub → 手机完整联调、媒体代理及硬解播放回归。

iOS 按 v2 协议交接，尚未实现；uni-app 无工程。本轮协议测试采用虚构配置与隔离存储，不代表生产上线验收。

## Hub 管理后台 hash 路由

Hub 管理页改为 hash 路由，支持外部 nginx 任意物理子目录，剥离/保留前缀均可。管理地址如 /任意前缀/#/subscriptions，API/订阅链接仍使用物理前缀，不能带管理 hash。本轮仅 Hub 与共享文档变化，不修改 Android/iOS 工程；既有已分发订阅链接仍要求原物理入口可达。
