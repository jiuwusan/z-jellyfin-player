# 可选 HTTP 代理与直连

## 已确认行为

订阅未选择代理时直连 Jellyfin；选择代理时继续代理全部媒体流量。配置不完整或代理失败不自动直连。服务器地址必须从手机网络可达，保留路径前缀；账号、画质、字幕和音轨行为不变。Hub 不转发媒体。

管理后台的订阅代理选择增加「不使用代理（直连）」。保存仍是草稿，显式预览发布后生效。直连订阅的 proxyId 为空字符串；数据库无需迁移。最终快照省略 connection.proxy，客户端也接受 null；存在的代理对象必须完整有效，空对象不能直连。

Android 0.6.58（构建号 72）新增直连支持。Hub 对直连快照自动将最低构建号提升至 72；既有代理快照兼容规则不变。Android 明确使用 Proxy.NO_PROXY，避免继承系统 HTTP 代理；不移除系统 VPN 路由。API、图片、HLS、字幕共用本次连接的客户端，不附带代理认证头。模式切换按现有候选验证与播放中延迟应用流程，不回退为另一模式。

## 实施与验收

1. 先补 Hub 无代理草稿/预览/发布/读取、非法代理、最低版本和模式切换回归；Android 补缺失/null/空对象、直连路由和认证头隔离回归，先确认原实现失败。
2. 修改 Hub 领域配置、发布构建、脱敏预览和订阅表单；同步 Android 解析、运行设置、OkHttp 路由、设置显示及错误提示。
3. 同步协议、Schema 和跨端交接；iOS 仅归档，未实现。工作在各仓库当前分支，不提交、推送或部署。
4. 运行 Go test/vet、前端测试/类型检查/构建、Android 构建与真机回归。真实直连使用本地授权信息，不在文档或日志记录地址和凭据，不修改既有服务配置。
