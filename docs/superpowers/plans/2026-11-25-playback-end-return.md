# 播放结束自动返回实施计划

**目标：** 电影或剧集末集自然播完后返回原页面并恢复竖屏，保留现有自动连播与手动返回流程。用户已确认；在当前分支内实施，不自动提交。

**实施方式：** 按 writing-plans / executing-plans 流程在当前会话执行。范围为 Android 与共享需求，iOS 不在本轮实施。

- [x] 增加受控 instrumentation 检查：本地代理夹具与模拟播放器，无真实媒体进度写入；旧版因缺少结束处理状态而按预期失败。
- [x] `MainActivity.PlaybackPage` 区分相邻集未完成、失败与确认完成；只有响应包含当前集才能确认末集。电影无需查询相邻集。
- [x] 自然结束时复用播放器关闭回调。退出延迟至当前播放器事件结束，复核页面、播放器、前台、结束状态及拖动标记，消费完成标记以防重复。
- [x] 有下一集继续原有切集路径；查询失败、后台、暂停、拖到片尾、起播位置已在片尾、切轨中、播放失败均不自动返回。
- [x] 构建并运行受控检查，验证会话上报、播放器释放、竖屏恢复、返回回调和连播目标。同步需求及版本至 0.6.51。
- [x] 覆盖安装荣耀并清理测试包，保留订阅与账号偏好。

**验收边界：** 短片或受控播放器验证结束生命周期；不通过快进真实影片来冒充自然播放，也不改 Jellyfin、Hub、代理配置。真实长片从头至尾的自然结束不作为本轮自动化覆盖。

## 验证结果

Android 构建 `:app:assembleDebug :app:assembleDebugAndroidTest` 成功。荣耀 BVL-AN00（0.6.51 / 65）运行 `-e suite playback-end` 返回 `ALL_PASS`，覆盖电影结束、真实夹具相邻集响应延迟、下一集切换入口、响应缺少当前集、查询失败、重复事件、拖到片尾、片尾起播、暂停、后台、失败、缓冲和取消延迟退出，以及竖屏恢复、播放器释放和最终位置上报。

相邻集检查等待 UI 中明确的查询完成状态，不将线程池中的空任务完成当作查询已结束。下一集检查验证切集请求目标，不冒充真实视频首帧或解码验证。返回页面复用原有回调；本轮没有逐个重验所有首页、媒体库及详情页的长片实播返回位置。

已卸载荣耀专用测试包，重开主 App 可自动进入竖屏首页「继续观看」。主 App、订阅和账号偏好保留；本轮没有更新 OPPO、没有部署服务，也没有提交或推送。
