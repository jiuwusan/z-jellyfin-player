# 字幕兼容性补验与缓存 Implementation Plan

> 使用 executing-plans 在当前master实施，不新建分支，不自动提交或推送。用户已授权完成待优化清单第1、2项，不新增字幕调节界面。

**Goal:** 补验内嵌文本、复杂ASS及拖动同步；通过有界字幕缓存减少同一字幕重复下载。

**Architecture:** JellyfinApi实例持有仅内存的字幕LRU缓存，以完整同源字幕URI为键。24MiB总量、8项、10分钟有效期，单文件仍受16MiB下载上限约束；成功下载后缓存，失效/解析失败/手动重试移除，重新登录清空。代际编号阻止旧下载在清空后回填。播放器与字幕恢复链路保持不变。

**Tech Stack:** Java、Media3 1.8、现有instrumentation与荣耀。

## 选择与边界

缓存采用进程内存而非磁盘：不增加持久化媒体和认证清理负担，代价是App重启后重新下载。使用精确URI而非猜测删除查询参数：避免不同字幕/时间范围串用，代价是服务端变更地址后不会命中。只缓存独立文本，不缓存视频和烧录画面。真实服务和账号配置不修改。
