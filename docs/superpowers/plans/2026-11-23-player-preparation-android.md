# Android 播放器首次取流加载态

目标：实现已确认的[三态设计](../../prototype/large-type/播放器首次取流设计方案.md)，保留 HTTP 代理、授权、画质、字幕、音轨和连播功能。

范围：当前分支的 Android 播放器和共享验收文档。iOS 不实施，不修改服务配置，不自动提交或推送。

## 实施步骤与验证

- [x] 核对现有取流协商、Media3 首帧、切轨恢复、返回及会话上报链路。
- [x] 先添加受控真机检查，运行旧版并确认缺少准备态接口而失败。
- [x] `FullscreenPlaybackView` 增加横版封面、遮罩、150ms 延迟指示器、6 秒提示及失败操作；实际首帧后淡出；门控播放控件；清理计时器和过时动画。
- [x] `LibraryUi.playbackBackdrop` 复用现有图片缓存与代理图片请求，优先使用剧集横版背景，缺图不阻塞播放。
- [x] `MainActivity.PlaybackPage` 统一首次请求与重试；保留续播点、源、音轨、字幕、轨道参数、画质策略；用页面及请求身份过滤过时回调；沿用原切轨恢复逻辑。
- [x] 版本递增为 0.6.28（42），覆盖安装荣耀，保留加密设置。
- [x] 构建、现有 JVM 检查、三态受控真机检查和真实播放回归通过；静态检查的历史遗留错误单独记录，见[验收记录](../../requirements/播放器首次取流验收.md)。

## 评审重点

- 接口成功或播放器准备好不能当作视频首帧。
- 快速返回、重试或替换播放时，旧回调不能覆盖新页面。
- 重试不能重置播放位置、画质或轨道选择，也不能重复提交。
- 小屏横屏下重试、返回与底部控制不能互相遮挡。
- 不改系统网络，不写入新的代理或授权；不把技术错误码和媒体地址显示给用户。

执行记录：已完成首次 RED 与三态 GREEN；真实《魅影神捕》第 2 集通过首帧、续播、拖动、受控失败后真实重试、暂停恢复及返回检查，输入为 H.264 1920×804、60fps，解码器 c2.qti.avc.decoder。评审发现短屏失败按钮裁切，新增检查复现 RED；改为依据实际工具栏高度避让、短屏压缩提示间距、滚动说明与固定操作分离，640×360dp 检查 GREEN。首帧后恢复原播放器布局。二次只读评审无重要问题。

构建环境：JDK 21、Android SDK 36。此电脑的 JDK 使用默认 TEMP 时出现 Unix 域套接字连接失败，本轮通过构建进程环境 `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=E:/zcode/tmp` 指定临时目录后构建成功；未修改工程或系统环境配置。
