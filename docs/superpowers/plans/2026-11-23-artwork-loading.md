# Android 图片加载统一修复计划

按用户确认在当前分支实施，使用 writing-plans、test-driven-development 和 executing-plans；不提交或推送。

目标：首页、媒体库、合集、搜索、详情及播放器背景使用同一套可见区域图片加载；返回保留可复用图片，避免整页重新下载和淡入。

- [x] 将已有荣耀诊断升级为回归断言，先复现返回 36 次图片请求的问题。
- [x] 新建 `ArtworkLoader`：可见区域加载、小图/大图独立有界内存缓存、同键请求合并、连接代次隔离、离屏任务清理；缓存命中不做淡入。
- [x] `LibraryUi` 全部图片统一接入；相同剧集背景用资源键合并。`JellyfinApi` 保留详情原图请求无 maxWidth，仅本地采样解码到显示需要的尺寸。
- [x] 在荣耀验证实际图片请求、可见图片缓存命中、不同页面返回、并发合并、账号隔离及播放器回归。

边界：不修改服务端、代理、账号或播放画质；不引入磁盘缓存。当前页面视图继续沿用现有导航重建，但缓存命中同步绑定图片且不再为所有离屏卡片发请求。缓存回收或进程重启后仍可能重新取图。
